# Android CameraX 拍摄与质量提示

## 范围

`AND-003` 把首页的智能扫描、试卷净化和连续扫书三个入口接入同一套 CameraX 拍摄能力。当前工作包负责相机权限、后摄预览、点按对焦、曝光补偿、实时质量提示、手动快门和原图落盘；不在本工作包中实现上传、页面处理、自动快门、双页拆分或导出。

三种入口只表达后续处理意图：

- 智能扫描进入普通文档拍摄。
- 试卷净化进入试卷拍摄，净化仍由后续确定性处理链路完成。
- 连续扫书进入书页拍摄；当前仍使用手动快门，翻页检测和自动快门由 `BOOK-001` 实现。

## 模块与状态机

`:feature:capture` 独立封装 CameraX，不依赖认证、网络或仓储模块。`:app` 只负责从首页传入 `CaptureMode` 并处理返回导航。

拍摄状态固定为：

```text
WAITING_PERMISSION
  -> BINDING_CAMERA
  -> READY
  -> CAPTURING
  -> CAPTURED
  -> READY
```

权限拒绝、后摄不可用和原图保存失败进入显式错误状态。只有 `READY` 可以响应快门；重复点击不会并发创建文件。低质量提示不会禁用快门，用户可以强制保留带警告的页面，符合“提示而不丢失原始证据”的产品边界。

## 质量提示

`ImageAnalysis` 使用 `KEEP_ONLY_LATEST`，在单独线程最多每 250 毫秒抽样一次 Y 平面，避免质量分析阻塞预览。当前轻量指标只用于拍摄提示：

| 指标 | 默认阈值 | 提示 |
|---|---:|---|
| 平均亮度 | `< 0.18` | 环境过暗 |
| 平均亮度 | `> 0.88` | 曝光过高 |
| 相邻抽样亮度差 | `< 0.055` | 可能模糊，请稳定并点按对焦 |
| 极亮像素比例 | `> 0.12` | 可能存在反光 |

阈值基于归一化 Y 平面，不是最终页面质量结论。边界完整度、透视角度、遮挡、方向和 OCR 置信度仍由后续端侧或服务端处理复核。未经固定真机数据集校准前，不把“可以拍摄”解释为 v1.4 质量指标已经通过。

## 原图与安全

- 拍摄结果写入应用私有目录 `files/captures/originals`，文件名仅含时间戳和随机 UUID，不含用户名、手机号或识别文本。
- 后续增强、裁切和上传必须从原图派生，不能覆盖当前文件。
- 保存失败会删除可能残留的目标文件，并且不创建成功状态。
- 当前文件尚未进入 Room 队列或服务端项目；`AND-004` 将建立用户分区的离线队列、分片续传和清理策略。
- 不记录图像内容、绝对路径、焦点坐标或 CameraX 异常正文到普通日志。

## 自动化与人工门禁

自动测试覆盖质量阈值、非法帧输入、权限到拍摄的合法状态转换、未就绪快门、拍摄失败和原图状态。GitHub CI 使用固定 JDK 17、Gradle 8.9 与 Android 35 SDK 编译 CameraX/Compose 并执行单元测试和 Lint。

下列项目必须保留真机人工验收：

- 至少一台目标 Android 设备的权限首次授权、拒绝、再次授权和系统设置恢复。
- 后摄选择、预览方向、拍照方向、点按对焦、连续自动对焦和曝光补偿范围。
- 暗光、运动模糊、高光反射、白纸和不同厂商 Y 平面跨度下的阈值校准。
- 进后台、旋转限制、低内存回收、来电中断和连续拍摄原图完整性。

模拟器、Robolectric 或 CI 编译不能替代上述真机门禁。
