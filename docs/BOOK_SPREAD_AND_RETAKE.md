# 书籍双页逻辑页与单侧重拍

## 目标与边界

`BOOK-002` 把阶段 0 的双页拆分和保守去弯曲算法接入正式处理链路。一次展开书拍摄保留为不可变的物理原图，并按项目已保存的 `reading_order` 生成一个或两个逻辑页面。界面语言不参与阅读顺序判断。

低置信拆分只保留一个 `single` 逻辑页并要求人工复核，不生成不存在的另一页。算法输出不能覆盖物理原图，也不能补写被手指、装订或阴影遮挡的内容。

## 数据与文件血缘

- `book_capture_id` 标识一次物理拍摄；正常双页的左右逻辑页共享该标识及同一 `original_path`。
- `book_side` 固定为 `left`、`right` 或保守回退的 `single`。
- `book_split_status` 区分旧数据、等待拆分、已拆分、回退和单侧重拍。
- `book_logical_source_path` 指向左右独立裁切并按保守门禁决定是否去弯曲的派生源图。它与活动处理结果分别保存，项目删除和账号合并必须同时处理该文件。
- 拆分置信度、书脊位置、去弯曲前后分数、是否采用和回退原因保存在页面记录及质量证据中。
- 单侧重拍创建新的逻辑页面和新的不可变原图，旧逻辑页通过 `book_replaced_by_page_id` 指向替代页。默认页面列表和导出只使用当前页；所有者仍可按旧 ID 查看历史页及结果。

同一物理拍摄的同一侧只能有一条逻辑页记录，同一替代页也只能替代一个旧逻辑页。单侧重拍使用行锁串行化，同一旧页被再次重拍返回 `409`。

## 处理流程

1. 书籍上传先创建 `pending` 页面和普通处理任务。
2. Worker 从不可变物理原图检测非中心书脊，按显式阅读顺序排列逻辑页。
3. 左右侧分别执行裁切与保守去弯曲；只有边界几何分数满足改善门禁时才采用去弯曲图。
4. 第一逻辑页复用原页面记录，第二逻辑页追加记录和独立任务；后续页号在同一事务内顺延。
5. 每个逻辑页独立执行质量、OCR 和结果版本处理。Worker 重试不会再次拆分已建立的逻辑页。
6. 拆分不可靠时只处理原图为 `single`，写入 `book_split_review` 并要求人工复核。

## 接口与客户端

- `GET /v1/projects/{project_id}/pages`：只返回当前逻辑页，并按持久化页号排序。
- `POST /v1/pages/{page_id}/book-retakes`：接收 JPEG、PNG 或 WebP，只允许页面所有者替换 `left` 或 `right` 当前页；成功返回 `202` 和新逻辑页。
- 默认 JPG/PDF 导出排除已被替换的旧页；显式请求旧页 ID 也返回未找到。
- H5、Android 和 iOS 均显示左页、右页或单页标识，只在活动结果就绪时提供“重拍当前侧”。三端上传后立即切换到替代页，另一侧保持不变。

无权用户和管理员对单侧重拍统一得到 `404`，拒绝事件写入审计。Mock、Simulator 和合成图片只证明契约及回退可重复，不代表真实书籍指标已通过。

## 回滚与兼容

迁移 `20261021_0019` 为旧书籍页回填 `legacy`，其他旧页回填 `disabled`。新增响应字段均为兼容字段，API 修订为 `2026-10-21.1`；上一代客户端可忽略它们并继续读取当前页面列表。

回滚应用代码前应先停止新 Worker 和重拍写入，再降级到 `20261021_0018`。降级会删除逻辑页元数据列，但不会自动删除已生成文件；应先备份并按项目清单处理，禁止直接清空用户目录。

## 验收门禁

自动化必须覆盖左右顺序、从右到左顺序、单页回退、单侧替换、默认导出、重复重拍拒绝、IDOR、迁移、账号合并和项目清理。

产品指标仍需授权固定集和真机人工验收：至少 5 本书、1000 个逻辑页面、300 次双页取景，正确拆分率不低于 95%，顺序正确率不低于 99%；覆盖厚书、手指遮挡、非中心书脊和快速翻页。指标未达到时保持“等待人工验收”，不能用合成测试替代。
