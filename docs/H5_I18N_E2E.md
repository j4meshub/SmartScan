# H5 双语、浏览器 E2E 与无障碍门禁

## 双语词条

主界面和页面编辑器词条集中在 `apps/h5/i18n.js`。自动测试要求 `zh-CN` 与 `en` 的键集合完全一致，并检查 HTML 中全部 `data-i18n`、`data-editor-i18n`、替代文本和无障碍名称都能映射到两种语言。界面切换时同步更新 `html.lang`、可见文本、`aria-label` 和图片 `alt`。

代码标识符、API 枚举、文件格式与产品名可以保留英文；面向用户的状态、按钮、错误提示和无障碍名称必须提供中英文。

## 无障碍基线

- 键盘焦点使用明显的高对比轮廓。
- 系统要求减少动画时，过渡和动画缩短到近乎即时。
- 四角裁切控制使用可聚焦的 `slider` 语义，方向键每次移动 1%，并公开当前归一化坐标。
- 图像提供本地化替代文本；纯装饰图形从辅助技术隐藏。
- 表单控件继续由可见 `label` 命名，状态消息使用 `role=status` 或 `aria-live`。

此基线不能替代完整 WCAG 审计。屏幕阅读器手势、系统字体放大、高对比模式和企业微信 WebView 仍需真机人工验收。

## Chromium E2E

Playwright 使用固定锁文件依赖和本地静态服务器，不连接真实 API。测试通过浏览器路由提供内存 Mock，并用 axe-core 扫描 WCAG 2 A/AA 规则，覆盖：

1. 中文账号登录、打开项目、查看任务、键盘调整四角、创建导出，以及 Web Share 不可用时下载回退。
2. 英文可见文本、文档语言、导航和按钮无障碍名称，以及登录页和项目工作区的 WCAG 2 A/AA 自动扫描。
3. 已认证页面刷新后从 `#project=<id>` 恢复项目工作区。

运行命令：

```text
cd apps/h5
npm ci
npx playwright install chromium
npm test
npm run test:e2e
```

CI 在 Node.js 22 上安装 Chromium 及其系统依赖。失败时保留截图和 trace，测试产物由 `.gitignore` 排除，不进入仓库。

## 人工门禁

Android 企业微信内置浏览器、真实相机、4G/5G 弱网切换、系统分享目标、中文输入法和屏幕阅读器仍保持“等待人工验收”。桌面 Chromium 自动测试通过不得被解释为这些真机门禁已经完成。
