# iOS AVFoundation 拍摄与 Vision 提示

## 范围

`IOS-003` 把智能扫描、试卷净化和连续扫书三个入口连接到同一套 iOS 拍摄能力。本工作包负责相机权限、后摄预览、点按对焦、曝光补偿、Vision 文档矩形、实时质量提示、手动快门、原图落盘和方向证据。

上传、后台恢复、页面编辑和导出分别属于 `IOS-004`、`IOS-005`。连续扫书当前仍使用手动快门，翻页识别与自动快门由 `BOOK-001` 实现。

## 状态机

```text
等待权限 -> 绑定相机 -> 就绪 -> 拍摄中 -> 已保存 -> 就绪
                         \-> 显式失败
```

未就绪时快门事件会被忽略，避免重复拍照并发写入。保存失败可以直接返回已经配置的相机；权限或相机失败需要重新检查权限并绑定。离开页面会停止会话，重新进入后复用已完成配置。

## 画面分析

`AVCaptureVideoDataOutput` 使用 `alwaysDiscardsLateVideoFrames`，在独立串行队列中最多每 250 毫秒分析一帧：

| 指标 | 默认阈值 | 用户提示 |
|---|---:|---|
| 平均亮度 | `< 0.18` | 环境过暗 |
| 平均亮度 | `> 0.88` | 曝光过高 |
| 相邻采样梯度 | `< 0.055` | 请稳定并点按对焦 |
| 极亮像素比例 | `> 0.12` | 可能存在反光 |
| Vision 矩形置信度 | `< 0.60` 或无矩形 | 请对齐完整文档 |

Vision 使用后摄方向映射执行 `VNDetectRectanglesRequest`，只显示最高置信矩形。矩形和质量指标都是轻量提示，不会禁止手动快门，也不替代服务端透视、OCR 或复核。

## 原图与方向证据

拍照保存 `AVCapturePhoto.fileDataRepresentation()` 返回的 JPEG，不执行重编码、裁切、滤镜或旋转。每次拍摄生成：

```text
<随机 UUID>.original.jpg
<相同 UUID>.evidence.json
```

证据包含 UTC 时间、扫描模式、设备方向、照片 EXIF 方向、像素尺寸、质量指标和拍摄时矩形。两者位于 `Application Support/SmartScan/captures/<用户 ID SHA-256>/`，使用“首次解锁后可访问”的完整文件保护；任一写入失败都会删除成对残留。文件名和目录不包含用户名、手机号或 OCR 文本。

## 权限和隐私

- `NSCameraUsageDescription` 同时提供英文和简体中文。
- 只选择后置广角相机，不上传实时预览帧，也不把像素、路径或错误正文写入普通日志。
- 点按坐标由预览层转换为相机设备坐标，只用于对焦与曝光，不持久化。
- 质量提示不会自动删除或替换原图。

## 自动化与人工门禁

Simulator 单元测试覆盖状态转换、非法快门、保存失败恢复、质量阈值、方向映射、用户目录隔离、原图字节不变和证据可解码。GitHub macOS Runner负责工程生成、Swift 编译和测试。

以下项目必须使用目标 iPhone 人工验收：首次授权/拒绝/系统设置恢复、后摄选择、预览与照片方向、点按对焦、曝光范围、锁屏与来电中断、暗光/运动/反光阈值、连续拍摄内存及原图完整性。模拟器无真实相机，不能替代这些门禁。
