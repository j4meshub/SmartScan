# 设备会话与刷新令牌

`ACC-004` 在既有随机访问令牌上增加设备维度、短期访问令牌和单次轮换刷新令牌。服务端只保存访问令牌和刷新令牌的 SHA-256 摘要，明文只在签发时返回给客户端。

## 签发与兼容

新客户端在注册、密码登录、企业微信回调或手机号绑定时发送：

| Header | 要求 |
|---|---|
| `X-Device-ID` | 客户端生成并稳定保存的 8 至 64 位标识，只允许字母、数字、点、下划线、冒号和连字符 |
| `X-Device-Name` | UTF-8 设备名经过百分号编码后的 ASCII Header，解码后最多 100 个字符且不能含控制字符 |
| `X-Device-Platform` | 2 至 32 位小写平台标识，例如 `web`、`android`、`ios` 或 `wecom` |

带设备头的新客户端获得 15 分钟访问令牌和 30 天刷新令牌。缺少 `X-Device-ID` 的旧客户端仍获得兼容的 24 小时访问令牌，同时返回可忽略的新增字段；服务端为每次旧登录生成独立 legacy 设备 ID，避免破坏现有多端登录。

`TokenResponse` 增量增加 `refresh_token`、`refresh_expires_at`、`session_id` 和 `device_id`，既有 `access_token`、`token_type` 与 `expires_at` 保持不变。

## 刷新与重放防护

`POST /v1/auth/refresh` 接收刷新令牌并执行数据库行锁轮换：

1. 原刷新令牌标记为已消费并关联下一令牌。
2. 同一设备会话的访问令牌摘要被替换，旧访问令牌立即失效。
3. 返回新的访问令牌和刷新令牌；刷新令牌不能再次使用。
4. 已消费刷新令牌再次出现时视为可能泄露，撤销整个设备会话及该会话全部刷新令牌，包括并发请求刚取得的新令牌。
5. 用户停用、账号合并、设备撤销或令牌过期时拒绝刷新。

PostgreSQL 并发测试使用两个连接同时轮换同一令牌，门禁要求恰好一次成功、一次重放，并最终撤销整个令牌族。

## 设备管理接口

- `GET /v1/me/sessions`：列出当前用户仍可访问或刷新的设备会话，并标记当前会话。
- `DELETE /v1/me/sessions/{session_id}`：撤销本人的指定设备；跨用户或不存在 ID 统一返回 `404`。
- `DELETE /v1/me/sessions`：撤销当前用户全部设备，包括当前请求设备。
- `POST /v1/auth/logout`：撤销当前设备及其刷新令牌。

密码修改保留当前设备并撤销其他设备；管理员角色/状态变更、账号合并和后续账号删除撤销全部设备。每次受保护请求仍实时检查用户状态，因此停用不会等待访问令牌过期。

## 迁移与回滚

`20261020_0009` 为既有 `sessions` 增加设备 ID、名称、平台和最后活动时间，并为每条旧会话回填唯一 `legacy:<session-id>`；同时创建刷新令牌链表及会话索引。

降级到 `0008` 会删除全部刷新令牌和设备元数据，但保留当前访问令牌及其原有效期。生产降级前应先让新客户端回退到只使用访问令牌的版本，否则客户端会因刷新接口消失而要求重新登录。
