# 管理接口、权限矩阵与审计

## 角色边界

管理端按层级执行最小权限：

- 普通用户不能进入 `/v1/admin/*`；失败尝试写入 `denied` 审计。
- 管理员只能查看和管理普通用户，不能枚举、读取或修改其他管理员与超级管理员。
- 超级管理员可以查看和管理普通用户与管理员，但不能修改、停用、撤销会话或删除自己，也不能创建第二个超级管理员。
- 目标不存在与目标超出当前角色范围统一返回 `404 user not found`，同时记录失败动作。
- 首次密码未修改的管理员不能执行管理操作。

角色修改仅允许超级管理员执行，目标角色只能是 `user` 或 `admin`。账号状态只允许在 `active` 与 `disabled` 之间切换；处于删除流程的账号必须通过删除撤销接口恢复，不能绕过状态机直接改回。

## 用户、会话与删除管理

`GET /v1/admin/users` 保持列表响应兼容，并增加 `role`、`status`、`q`、`limit` 和 `offset` 查询参数；总数通过 `X-Total-Count` 返回。管理员的列表天然只包含普通用户，超级管理员可查看全部未删除账号。

管理操作包括：

- `PATCH /v1/admin/users/{id}/role`：超级管理员调整普通管理员层级，并撤销目标全部会话。
- `PATCH /v1/admin/users/{id}/status`：按角色层级停用或恢复账号，并撤销目标全部会话。
- `DELETE /v1/admin/users/{id}/sessions`：撤销目标全部访问令牌和刷新令牌。
- `POST /v1/admin/users/{id}/account-deletion`：要求精确输入目标用户名和 3 至 500 字原因，进入与用户自助删除相同的 7 天冷静期和 Worker 清理流程。
- `GET /v1/admin/account-deletions`：按状态分页查看当前角色可管理的删除请求。
- `POST /v1/admin/account-deletions/{request-id}/cancel`：在清理开始前撤销请求，并记录撤销原因；旧会话不恢复。

管理员发起删除不是直接物理删除，仍使用 `ACC-005` 的原子文件隔离、数据库清理、重试和手机号复用隔离边界。

## 审计查询

`GET /v1/admin/audit` 支持 `actor_user_id`、`target_user_id`、`action`、`result`、`since`、`until`、`limit` 和 `offset`，并通过 `X-Total-Count` 返回过滤后总数。

普通管理员只能看到自己发起的管理事件，以及目标为当前普通用户的事件；超级管理员可以查看全部审计。成功与失败的角色修改、状态修改、跨用户读取、会话撤销、删除申请、删除撤销和管理入口拒绝均写入追加式审计。审计查询本身也记录 `list_audit_logs`，但当前查询响应不包含本次新事件。

审计表在 PostgreSQL 中由触发器禁止更新和删除。查询参数不会改变这一不可变边界；分页只是限制返回量。

## 迁移与回滚

`20261020_0011` 为删除请求增加发起人、来源和申请原因。既有请求回填为 `self_service`，发起人回填为原用户 ID。`20261020_0012` 独立增加撤销原因，避免修改已经应用的迁移。

降级到 `20261020_0011` 会丢失撤销原因；继续降级到 `20261020_0010` 会删除其余管理元数据。降级不会取消删除请求，也不会恢复已经撤销的会话或已清理的数据。生产降级前必须导出所有管理发起的待处理请求和原因，并停止管理写入与删除 Worker。
