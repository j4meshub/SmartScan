# 系统架构

```text
企业微信 H5 ─┐
Android ─────┼── HTTPS / Nginx ── FastAPI ── PostgreSQL
iOS ─────────┘                         │          │
管理后台 ──────────────────────────────┘          └─ 带租约的 CPU 任务
                                                    │
                                            用户隔离文件存储
                                                    │
                                            可选 AI 网关（关闭）
```

H5 使用稳定但不含身份信息的设备 ID 获取短期访问令牌与单次刷新令牌；令牌只存放在标签页 `sessionStorage`，设备 ID 单独存放。企业微信 OAuth `state` 由服务端摘要与 `HttpOnly` Cookie 双重约束，回调缺少可信手机号时必须消费专用短信挑战。详见[H5 登录与企业微信绑定](H5_AUTH.md)。

H5 页面编辑通过鉴权 Blob 预览当前活动结果，四角裁切、滤镜和旋转均在服务端追加不可变结果版本；页序更新要求提交完整页面集合。原图不覆盖，编辑后 OCR 失效等待重跑。详见[H5 页面编辑](H5_PAGE_EDITOR.md)。

H5 文件工作区使用 URL 片段恢复当前用户项目，从所有者项目列表验证目标后再加载页面、任务和导出记录。活动任务短轮询随弹窗关闭而停止；导出文件始终先经过 API 鉴权，再使用 Web Share 或本地下载，不生成带令牌的公开链接。详见[H5 项目恢复、任务与文件分享](H5_FILES_AND_SHARE.md)。

H5 的中英文词条由独立模块统一维护，文本、替代文本和无障碍名称共享键一致性门禁。Playwright 以本地静态服务器和内存 Mock API 验证完整浏览器流程，不读取真实账号或用户文件。详见[H5 双语、浏览器 E2E 与无障碍门禁](H5_I18N_E2E.md)。

Android 工程按应用、仓储、网络和领域模型分层。Compose 导航与 Android 生命周期留在 `:app`，DTO 和请求头策略位于 `:core:network`，界面只通过仓储消费领域对象。远端 API 强制 HTTPS，默认根地址使用不可解析域名，访问令牌不进入 URL。详见[Android 分层工程与 API 客户端](ANDROID_ARCHITECTURE.md)。

Android 会话密钥由 Keystore 管理，令牌以 AES-GCM 密文保存在应用私有存储；Room 只缓存可重新下载的项目元数据，并以 `owner_user_id` 作为所有查询的显式分区参数。注销远端失败不会阻止本地会话和当前用户缓存清理。详见[Android 身份、Keystore 与用户分区缓存](ANDROID_AUTH_AND_CACHE.md)。

## 权限与所有权

权限判断以不可变数据所有者的当前角色为依据。管理员读取数据不会改变所有权，并且会写入审计事件。即使当前账号是管理员，用户端项目列表仍始终使用当前用户的所有者 ID 进行限制；跨用户访问只允许通过管理后台接口进行。

管理权限按角色层级收缩：管理员只能读取和管理普通用户，超级管理员可以管理普通用户与管理员，但唯一超级管理员始终不可被其他接口修改。管理列表和审计列表使用增量查询参数分页，成功与失败动作均进入追加式审计；超出角色范围和不存在目标统一返回 `404`。详见[管理接口、权限矩阵与审计](ADMINISTRATION_AND_AUDIT.md)。

## API 分层

FastAPI 入口 `main.py` 只负责应用创建、中间件、迁移门禁、超级管理员初始化和路由装配。公开端点按职责拆分为认证与个人账号、扫描项目与上传、管理后台三个路由模块。

跨路由业务规则位于 `domain_services.py`，包括会话签发、超级管理员初始化、上传过期与文件签名判断；资源所有权查询、行锁和上传视图装配位于 `repositories.py`。路由层负责 HTTP 参数、状态码和事务编排，不直接承载可复用的所有权规则。公开路径、方法、成功状态码及核心响应模型由契约测试固定，重构不能静默改变 `/v1` 行为。

接口契约采用当前快照与上一代客户端基线双重保护：运行时 OpenAPI 必须精确匹配当前快照，兼容检查器再禁止当前快照破坏上一基线。H5、管理后台、Android、iOS 只登记实际消费的 `operationId`；弃用必须同步登记替代方案和至少 90 天窗口。响应头发布 `v1` 大版本与契约修订号。详见[v1 API 契约冻结与客户端兼容](API_COMPATIBILITY.md)。

## 统一身份与手机号保护

`users` 是稳定用户主体和所有权锚点，`user_identities` 保存 Provider 登录主体及本地凭据，`verified_phones` 保存独立手机号验证事实。新验证号码同时写入版本化 HMAC、掩码和 AES-256-GCM 认证密文；密文关联用户 ID 与密钥版本，不能跨账号复制使用。查重会计算当前配置中全部 HMAC Pepper 版本，避免轮换窗口内重复注册。

旧基线无法从 HMAC 与掩码恢复原号，因此迁移只标记为 `unavailable`，等待下一次可信验证补齐。密钥由运行环境 Secret 注入，数据库只保存版本 ID；详细轮换与回滚边界见[手机号数据保护与密钥轮换](PHONE_DATA_PROTECTION.md)。

短信验证使用短生命周期挑战，验证码仅以服务端 HMAC 保存。手机号和直连 IP 的窗口计数分别使用唯一伪名键与数据库行锁，挑战成功、过期或耗尽后不可重放；Provider 与限频边界见[短信验证码挑战与限频](SMS_VERIFICATION.md)。

企业微信登录先消费短期一次性 state，再从固定官方 API 获取成员身份。Provider 身份是长期绑定主键，可信手机号只用于首次唯一候选匹配；缺失手机号时使用一次性绑定票据衔接短信挑战。详见[企业微信 OAuth 登录与安全绑定](WECOM_OAUTH_BINDING.md)。

历史双账号合并要求当前会话加同手机号短信强验证，并只处理恰好两个、身份 Provider 互补的普通账号。数据库归属在单一事务内迁移，文件先复制校验再原子落位，提交失败删除新副本，提交成功后撤销双方会话。既有审计事件不改写，旧 ID 到 canonical ID 的映射保存在 PostgreSQL 触发器保护的合并审计表。详见[账号合并与冲突处理](ACCOUNT_MERGE.md)。

每条 `sessions` 记录代表一个设备会话和当前访问令牌；`refresh_tokens` 保存单次轮换链，只存摘要。刷新时行锁串行化同一令牌，重放会撤销整个设备令牌族。新客户端使用短访问令牌，未发送设备标识的旧客户端保留兼容有效期。详见[设备会话与刷新令牌](DEVICE_SESSIONS.md)。

账号删除使用独立请求状态机。申请后用户立即进入 `deleting` 并撤销全部会话，7 天内可凭新的短信强验证撤销；到期后 Worker 先把用户目录原子移入隔离区，再事务清理资源并擦除隔离目录。数据库清理已提交但文件擦除失败时保持 `cleanup_pending` 重试。手机号只以版本化 HMAC 保留 30 天复用隔离，用户主体仅留下不可登录墓碑和最小审计关联。详见[账号删除、冷静期与手机号复用隔离](ACCOUNT_DELETION.md)。

## 任务处理

Worker 使用数据库行锁和随机租约令牌获取任务，并用心跳延长有限租约。客户端断开不会取消已经受理的任务；租约过期后，其他 Worker 可以用新令牌接管，旧 Worker 无法再提交。可重试失败按指数退避重新排队，达到上限进入最终失败；所有者取消会立即使租约失效。详见[作业状态机、租约与恢复](JOB_STATE_MACHINE.md)。

原图始终保留，处理结果以页面内递增版本写入独立文件和 `page_results`；`scan_pages` 只保存当前活动版本兼容指针、结构化质量、累计旋转和独立复核状态。详见[页面版本、质量与复核](PAGE_VERSIONS_AND_REVIEW.md)。

基础 OCR 在 CPU Worker 内通过固定版本、只读本地模型执行，不经过外部 AI 网关。Worker 对四个正交方向分别识别并在每次推理后续租，只在非零方向具有明确分数优势时旋转处理图。OCR 全文、最终行框、置信度、模型版本和标题候选与活动页面结果版本绑定；手动旋转会使旧 OCR 失效。详见[基础 OCR、方向融合与安全命名](OCR_PIPELINE.md)。

导出请求通过 `scan_exports` 冻结页面顺序、活动结果版本、质量档位和实际 OCR 使用证据；`export_artifacts` 保存每个 JPG 或 PDF 制品的所有者、路径、哈希和大小。多页 JPG 保持多制品语义，多页 PDF 合并为单一制品。文本层只消费与活动结果版本一致的 OCR 行框，缺失或过期时生成纯图像 PDF。文件位于用户隔离目录并原子落盘，下载传输边界由后续 `FILE-001` 承担。详见[JPG/PDF 导出与 OCR 文本层](EXPORT_PIPELINE.md)。

文件下载先由 API 完成所有者鉴权和审计：本地直接返回支持 Range 的文件响应，Compose 环境返回指向 Nginx `internal` 位置的 `X-Accel-Redirect`。上传取消与过期分片由 Worker 幂等回收；项目删除先在数据库保存文件清单并删除业务资源，再以 `cleanup_pending` 状态重试文件擦除。详见[文件下载、上传取消与项目清理](FILE_LIFECYCLE.md)。

## 数据库版本管理

数据库结构由 Alembic 迁移版本管理。开发环境可在 API 启动时自动升级；生产 Compose 将迁移作为独立的一次性服务，只有迁移成功后才允许 API 和 Worker 启动。Worker 自身只检查版本，不创建表也不修改结构，避免多个进程并发迁移。

`20261020_0001` 等价于提交 `1d5a9d6` 的 SQLAlchemy 模型，`0002` 安装 PostgreSQL 唯一超级管理员等保护，`0003` 拆分登录身份与已验证手机号，`0004` 增加手机号认证密文和密钥版本。对没有 `alembic_version` 的旧基线库，迁移入口会先核对全部表和列；只有完全匹配时才接管并标记为 `0001`，残缺或未知结构会停止而不是猜测修改。后续变更遵循 expand/migrate/contract，并保持当前及上一客户端兼容。

文档和试卷任务先在缩放副本上执行灰度化、模糊抑噪、Canny 边缘提取和形态学闭运算，再从轮廓中筛选面积达到阈值的凸四边形。坐标映射回原尺寸后执行透视变换，最后完成对比度和锐度增强。检测阈值可通过 `SMARTSCAN_VISION_DOCUMENT_MIN_AREA_RATIO` 调整，检测计算的最长边可通过 `SMARTSCAN_VISION_MAX_DETECTION_DIMENSION` 限制。

这条处理链采用保守回退：没有找到可信四边形时不裁切内容，仍输出完整画面的基础增强版本，作业正常完成并把页面复核状态设为 `pending`。原图和既有结果版本不会被覆盖，因此算法升级或误裁切时可以回看和重新处理。

## 分片上传与断点续传

客户端先使用项目 ID、文件信息、整文件 SHA-256 和幂等键创建上传会话。服务端返回固定分片大小和已确认的分片序号；客户端只补传缺失分片。每个分片都校验预期大小和 SHA-256，完成时再按顺序组装并校验整文件大小、整文件 SHA-256 和图片文件签名。完成接口可以安全重试，同一上传会话只创建一个页面和一个处理任务。

上传会话和临时分片按所有者 ID 隔离，其他用户即使知道上传 ID 也只能得到 `404`。H5 将项目 ID 和幂等键保存在本地，网络中断后重新提交同一文件即可继续上传。

## 外部 AI 边界

外部 AI 是增强能力，而不是基础流程的依赖。独立网关在启动时从环境 JSON 建立不可变 Provider 注册表，覆盖专业 OCR、OpenAI-compatible 和自定义协议；默认定义全部关闭，密钥只通过环境变量名引用，状态接口不返回引用名称或值。业务 API 与 CPU Worker 不依赖网关，关闭或不启动网关不会改变核心流程。详见[可选视觉 AI Provider 注册与配置](AI_PROVIDER_REGISTRY.md)。

AI 出站目标和媒体前缀只能来自启动配置，不接受调用方完整 URL。每次调用校验全部 DNS 地址，默认只允许公网；自定义 VLM 可显式声明窄范围受控网段。HTTPS 套接字固定连接已验证 IP，但 TLS SNI、证书和 Host 继续使用原域名；任何重定向、压缩/非 JSON 响应和超限请求均失败关闭。详见[可选视觉 AI 出站网络与媒体安全](AI_NETWORK_SECURITY.md)。

AI 可靠性状态保存在 PostgreSQL，而不是各 Uvicorn Worker 的内存。每个 Provider 独立配置超时、最多一次重试、熔断、半开探针、并发、滚动一分钟频率和 UTC 日费用上限；调用先预留最坏费用，只有进入网络发送阶段才实际按保守上界计费。租约使进程崩溃后的并发槽可回收，脱敏证据不保存用户、页面、媒体 URL/令牌、密钥或模型原文。详见[可选视觉 AI 可靠性、熔断与费用门禁](AI_RELIABILITY_COST.md)。

AI 任务使用版本化的分类、方向、标题、页码、公式/表格、净化复核和双页复核 Schema。Provider 原始输出经过严格 JSON、任务身份和业务规则校验后，只形成绑定 Provider、模型、页面基础版本和媒体摘要的候选证据，不能直接修改业务数据。详见[可选视觉 AI 结构化任务与结果契约](AI_STRUCTURED_TASKS.md)。

AI 候选系统使用同一份已授权、已脱敏且按来源分组切分的固定数据集离线比较。评估输入固定数据集、模型、框架、提示词、适配器和配置版本，输出准确率、幻觉率、结构化成功率、延迟与成本；公开报告不含图片、原始路径或模型原文。评估器不负责启用 Provider，也不把合成数据或 Mock 结果当成真实验收。详见[可选视觉 AI 固定评估](AI_FIXED_EVALUATION.md)。

隔离 staging 使用独立 Compose 项目和 `/srv/smartscan/staging/` 主机根目录，应用继续启用生产安全校验。数据库、入口和出站网络分层；只有打包 H5/后台/Nginx 的固定 digest Web 镜像绑定主机回环端口，数据库与 API 不直接发布端口。目标服务器只拉取镜像并显式运行迁移，不挂载仓库源码或现场构建。详见[隔离 staging 部署基线](STAGING_DEPLOYMENT.md)。

公网 TLS 由主机 Nginx 终止，再只代理到回环地址上的 staging Web Nginx。主机层负责 TLS 1.2/1.3、HTTP/2、真实客户端限频和安全日志；容器层负责静态入口、API 前缀转换及鉴权后的 `internal` 文件发送。BBR 变更前后以只读快照固定内核、拥塞控制和 qdisc，回滚始终使用实际原值；配置生效只允许进入受控网络对照，不能直接解除上线门禁。详见[TLS、内部文件发送与 BBR 基线](NETWORK_AND_FILE_DELIVERY.md)。

运维指标只通过内部数据网络暴露：API 多进程请求指标与数据库派生的队列、租约、审计、AI 和磁盘指标由 Bearer Token 保护，公网 Nginx 不代理内部路径。Worker 定期在 PostgreSQL 保存不含用户数据的存活心跳；任务真实性仍由独立租约决定。新上传、组装和 Worker 领取分别受到队列高水位、每用户并发、用户目录实际占用、未接收上传预留和磁盘最低空间约束，下载与清理不被写入保护阻断。Prometheus、Alertmanager 与 Node Exporter 只在显式 monitoring Profile 中启动且无主机端口。详见[监控、容量配额与磁盘保护](MONITORING_AND_CAPACITY.md)。

## 单机部署基线

首版部署由 Nginx、API 服务组、CPU Worker 组、PostgreSQL 和用户隔离文件目录组成。上传受理与 CPU 处理解耦，保证重任务排队时登录、查询和下载鉴权仍能响应。后续只有在实际容量指标超过单机边界后，才引入独立 Worker 或高可用组件。
