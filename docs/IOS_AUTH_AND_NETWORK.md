# iOS 身份、Keychain 与网络

## 范围

`IOS-002` 为 iOS 客户端实现短信注册、本地账号登录、设备会话恢复、刷新令牌轮换、安全退出、API 基础客户端和用户缓存分区。接口沿用已冻结的 `/v1/auth/*` 与 `/v1/me`，不为 iOS 创建私有身份协议。

企业微信授权、账号删除、设备管理和项目同步分别由后续功能或既有服务端能力承接，本工作包不以空界面冒充完成。

## 会话与设备身份

- 访问令牌、刷新令牌、有效期、会话 ID、服务端设备 ID 和当前用户 ID 编码为一个完整会话，保存在 Keychain 的 `device-session-v1` 项。
- 稳定客户端设备 ID 单独保存在 `device-identifier-v1` 项，格式为 `ios:<UUID>`；退出时不删除它，便于服务端正确识别同一设备。
- 两项都使用 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`，不会通过 iCloud Keychain 同步到其他设备。
- 刷新成功后完整替换会话；响应缺少刷新令牌、会话 ID 或设备 ID 时拒绝保存，不能退化为只保留访问令牌。
- 会话密文损坏或无法解码时删除该会话项并回到未登录状态，不尝试恢复部分凭据。

## 网络边界

应用从生成的 Info.plist 读取 `SMARTSCAN_API_BASE_URL`。工程默认值为 `https://api.invalid/`，因此未显式配置的构建不会连接开发或生产环境。正式环境必须通过受控构建配置注入 HTTPS 地址；HTTP 只允许 `localhost`、`127.0.0.1` 或 `::1` 回环测试地址。

每个请求发送以下不含凭据的设备元数据：

```text
X-Device-ID: ios:<稳定 UUID>
X-Device-Name: <百分号编码的设备名称>
X-Device-Platform: ios
```

只有认证接口请求附带 `Authorization: Bearer <access token>`。用户名、密码、短信验证码和刷新令牌只进入 JSON 请求体，不进入 URL、查询参数或日志。

## 恢复、刷新与退出

启动时先读取本地会话并调用 `/v1/me`。访问令牌返回 `401` 时只执行一次刷新令牌轮换，再重试 `/v1/me`；刷新也被拒绝时立即清除本地会话和当前用户缓存。其他网络故障不会被伪装为未登录成功。

退出先尝试撤销服务端会话，无论网络是否可达都会清除本地会话与当前用户缓存。网络失败会向用户说明“已在本机退出”，避免用户误以为服务端撤销已经完成。

## 用户缓存隔离

缓存根目录位于 Application Support 的 `SmartScan/users`。每个用户目录名为用户 ID 的 SHA-256，不直接暴露原始标识；项目 JSON 只在对应目录中读写。退出只清除当前用户目录，其他账号的数据不会被读取或删除。

后续 `IOS-004` 的上传队列必须继续把用户 ID 作为每次查询和任务恢复的必要条件，不能仅依赖当前登录账号隐式过滤。

## 测试与人工门禁

Simulator 自动测试覆盖：完整会话校验、令牌轮换、设备 ID 稳定性、损坏会话清理、设备请求头、Bearer 边界、HTTP 错误、登录后用户绑定、`401` 刷新恢复、远端退出失败的本地清理，以及跨用户缓存隔离。

以下项目仍需真机人工验收：锁屏后 Keychain 访问、卸载重装后的设备 ID 行为、备份/迁移边界、网络切换、动态字体、VoiceOver 和真实短信。正式 API 域名、Apple Team、Bundle ID 与签名材料不得提交到仓库。
