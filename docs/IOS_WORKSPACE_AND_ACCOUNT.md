# iOS 工作区、导出分享与账号删除

## 范围

`IOS-005` 在 iOS 登录态内接入现有项目、页面编辑与导出接口，并提供 PDFKit 预览、系统 Share Sheet 和应用内账号删除。所有内容读取继续使用 Bearer 会话，未授权与不存在资源沿用服务端统一 `404` 边界。

本工作包不改变服务端图像算法、导出格式或账号删除时序，也不在客户端伪造处理结果。编辑操作创建新的处理结果版本，原始扫描件始终保留。

## 工作区与页面编辑

工作区从 `/v1/projects` 恢复项目，项目详情并行读取页面和历史导出。网络不可用时只允许展示当前用户缓存的项目摘要，页面内容、编辑和导出不会用其他用户数据回退。

页面能力包括：

- 完整页序上移和下移，提交前拒绝空列表与重复 ID；服务端继续验证必须包含项目全部页面。
- 每次旋转 90 度；服务端生成新的活动结果版本。
- 四个归一化角点，每个 `x`、`y` 都限制在 `0...1`；滤镜限定为 `original`、`enhance`、`grayscale`、`bw`。
- 页面预览始终读取活动版本；编辑、旋转后丢弃旧预览并重新鉴权下载。
- 复核只显式提交 `confirmed`，不会因为客户端预览成功自动确认低质量页面。

## 导出、PDFKit 与系统分享

用户可选择 JPG 或 PDF，以及清晰、均衡、小体积三档质量；OCR 文本层只在 PDF 中启用。客户端保存服务端返回的导出记录，生成中或失败时必须显式刷新，不用本地计时假装完成。

制品从 `/v1/export-artifacts/{id}/content` 鉴权下载。临时文件以流式方式复制到：

```text
Application Support/SmartScan/downloads/<用户 ID SHA-256>/exports/
```

复制过程中计算 SHA-256，并严格比较 `size_bytes` 与 `sha256`。任一不匹配都会删除临时文件，不进入 PDFKit 或 Share Sheet。页面预览使用同一用户分区，但服务端当前没有为预览响应声明摘要，因此只作为可丢弃缓存，不替代原图或导出证据。

PDF 使用 `PDFKit.PDFView` 只读预览；JPG 使用本地图片预览。分享只把校验后的本地 URL 交给系统 `UIActivityViewController`，应用不上传到第三方或预选外部接收方。

## 账号删除与冷静期

申请删除必须同时满足：

1. 当前仍有有效会话。
2. 输入 E.164 格式手机号。
3. 使用目的为 `account_deletion` 的独立短信挑战。
4. 输入与当前账号完全一致的用户名二次确认。

服务端接受请求后撤销会话，并按既有规则进入 7 天冷静期。客户端随后清除当前用户的项目缓存、捕获原图、上传队列、预览和导出文件；清理路径只使用用户 ID 的 SHA-256 摘要。即使本地某项清理失败，也明确告知“服务端删除已安排”，不会误导用户重复提交。

取消删除不要求旧登录态，使用目的为 `account_deletion_cancel` 的独立短信挑战。重新登录本身不会取消删除。

## 自动化与人工门禁

Simulator 自动测试覆盖接口路径和请求体、四角/页序拒绝、导出大小与摘要、跨用户目录、离线项目摘要、短信目的、会话清除和用户分区清理。macOS CI 负责 XcodeGen、Swift 编译、PDFKit 链接和全部单元测试。

以下仍需目标 iPhone 与 staging：大 PDF 内存与渲染、系统分享目标、文件提供器、磁盘不足、会话恰好过期、真实短信、7 天冷静期取消、服务端清理结果及 App Store 隐私/账号删除审核。Mock 与 Simulator 不能把这些门禁标为通过。
