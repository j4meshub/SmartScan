# 短信验证码挑战与限频

`SMS-001` 提供 `POST /v1/auth/sms/challenges`，注册请求可通过 `sms_challenge_id` 消费挑战。挑战固定 5 分钟有效、最多验证 5 次，成功后立即消费，不能重放。

## 安全边界

- 数据库只保存带服务端 Secret 的验证码 HMAC，不保存或返回验证码明文。
- 手机号限频键和直接连接 IP 均先做 HMAC；限频窗口使用独立唯一计数行和行锁，避免并发请求同时越过上限。
- 默认窗口 15 分钟，手机号最多 3 次、IP 最多 10 次；响应 `429` 并携带 `Retry-After`。
- 限频只使用 `request.client.host`，不信任客户端可伪造的 `X-Forwarded-For`。未来接入受控反向代理时，必须由部署层清洗并明确可信代理范围。
- 挑战错误、审计和 Provider 错误不包含手机号、验证码或 Secret。

## Provider 模式

| `SMARTSCAN_SMS_MODE` | 行为 |
|---|---|
| `disabled` | 返回 `503 sms_provider_disabled`，用于未配置短信的环境 |
| `mock` | 仅 development 可用，使用 `SMARTSCAN_DEV_SMS_CODE` 验证本地契约 |

生产禁止 `mock`。真实供应商、签名、模板、回执和密钥尚未冻结，因此本工作包只交付可替换 Provider 接口；Mock 通过不能代表真实短信验收。

## 兼容与迁移

开发环境暂时保留没有 `sms_challenge_id` 的固定码注册，避免破坏现有测试和旧开发客户端；生产从未允许该路径。新客户端应先申请挑战，再把挑战 ID 和收到的验证码一并提交注册。

迁移 `20261020_0005` 创建挑战表，`0006` 创建并发安全的限频窗口表。降级会删除挑战、尝试次数与限频状态；正式环境降级前应确认不会重新开放已耗尽或已消费挑战。
