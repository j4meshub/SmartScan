# 扫书条件自动快门

## 目标与边界

`BOOK-001` 为扫书模式提供无倒计时的条件自动快门。系统只有在确认发生翻页、画面连续稳定、清晰度和曝光可用、页面边界与书脊可识别、暗区遮挡比例不过高时才触发拍摄。任一条件不满足都会显示具体原因，手动快门始终可用。

该能力不会覆盖原图，也不声称当前启发式等同于手部检测模型。暗区比例只能作为保守遮挡信号；深色页面、阴影、插图和特殊装帧可能触发回退。低置信场景应使用手动拍摄。

## 状态机

状态按以下顺序推进：

```text
WAIT_PAGE
  -> PAGE_CHANGED
  -> WAIT_STABLE
  -> WAIT_FOCUS
  -> CHECK_LAYOUT_AND_OCCLUSION
  -> CAPTURE
  -> VERIFY
  -> ACCEPT_OR_RETRY
  -> WAIT_PAGE
```

- `WAIT_PAGE`：要求相邻亮度采样的归一化差值达到 `0.08`，防止同一页反复拍摄。
- `WAIT_STABLE`：运动分数不高于 `0.025`，且连续满足 3 帧。
- `WAIT_FOCUS`：复用端侧清晰度、曝光和高光判断。
- `CHECK_LAYOUT_AND_OCCLUSION`：边界置信度至少 `0.60`、书脊对比度至少 `0.035`、暗区比例不高于 `0.20`。
- `CAPTURE`：不显示固定倒计时，条件刚满足即调用与手动快门相同的原图保存路径。
- `VERIFY`：等待原图保存及进入本地上传队列，不以相机回调成功替代持久化成功。
- `ACCEPT_OR_RETRY`：成功后重新等待下一次翻页；失败保留明确重试状态，不静默跳页。

阈值是版本内固定的保守起点，真实样本门禁通过前不得以合成测试结果宣称可用率达标。

## 各端实现

### Android

- CameraX 分析帧每 250 毫秒计算运动、四边对比度、中心书脊对比度和暗区比例。
- 自动拍摄与手动拍摄共用不可变原图保存及入队回调；只有入队成功才重新等待下一页。
- 保存或入队失败进入可重试状态，用户可关闭自动快门或直接使用手动快门。

### iOS

- AVFoundation 亮度平面提供运动、书脊和暗区信号，Vision 矩形置信度作为边界信号。
- 原图和拍摄证据继续成对保存；新增指标均为可选字段，旧证据可以继续解码。
- 分析器只在串行分析队列读写，避免切换自动快门时与视频帧并发修改基线。

### H5

- 浏览器只提供尽力而为的单页自动拍摄：在缩小的视频帧上执行同一状态机，成功后仍需用户创建并上传项目。
- 浏览器摄像头、曝光、对焦和后台调度差异较大，因此界面明确保留手动快门与系统相机文件兜底。
- H5 当前不宣称具备原生端连续后台拍摄能力。

## 自动化证据

- Android、iOS、H5 均覆盖“必须先翻页”“连续稳定三帧”“各阻塞信号”“成功重新布防”和“失败重试”。
- Android 与 iOS 覆盖连续帧运动和中心暗书脊信号；H5 覆盖亮度采样及死循环回归。
- iOS 覆盖缺少新增可选字段的旧 `FrameQuality` JSON 解码。
- GitHub Runner 负责 Android 编译/Lint 与 iOS Xcode 16.4 Simulator 编译测试；本地 Windows 结果不能替代这些门禁。

## 人工验收门禁

在 `POC-005` 固定数据集之外，自动快门至少需要以下真实设备证据：

1. 不少于 5 本不同尺寸、纸张颜色和装帧形式的书。
2. 不少于 1000 个逻辑页面、300 次双页取景，包含手部遮挡、快速翻页、阴影、反光和深色插图。
3. Android 与 iPhone 各至少一台目标真机，记录误触发、漏拍、重复拍摄、对焦/曝光失败及单页等待时间。
4. 自动拍摄失败时原图不丢失、页序不被静默推进，手动快门和系统相机兜底均可完成流程。

真实数据集与目标真机尚未提供时，工作包只能进入“等待人工验收”，不能标记“完成”。
