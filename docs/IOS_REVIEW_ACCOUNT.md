# iOS 审核账号操作规程

## 原则

审核账号是专用普通用户，不得授予 `admin` 或 `super_admin`，不得复用员工、客户或生产支持账号。Apple 要求审核凭据有效、不会过期并能访问完整功能；详见[完成审核信息](https://developer.apple.com/help/app-review/before-submitting-for-review/complete-review)。凭据和短信取码方式只填写在 App Store Connect 安全字段或受保护的发布环境，禁止进入仓库、Issue、PR、截图和普通日志。

## 准备步骤

1. 在隔离 staging 或正式审核环境创建唯一审核手机号和 `user` 角色账号。
2. 准备不含个人信息、已获授权的示例项目，覆盖页面编辑、复核和 PDF/JPG 导出。
3. 保证登录后无需邀请、审批、企业内网或管理员操作即可进入完整流程。
4. 短信通道必须在审核时可用；如提供固定审核码或人工取码流程，只写入 App Store Connect 审核说明，并注明时区和响应窗口。
5. 使用与提交构建相同的生产配置完整走查，不使用开发 Mock 证明审核可用。
6. 检查应用内账号删除入口、7 天冷静期与取消流程。为防止一次审核删除后账号失效，准备可审计的重建步骤，但不要自动取消审核人员真实发起的删除请求。

## 审核期间

- 监控 API、Worker、短信和文件下载，但不得记录验证码、访问令牌或扫描内容。
- 若审核人员报告无法登录，先确认账号状态、短信、时间窗口和服务健康，不临时提升权限。
- 需要额外说明时通过 App Store Connect 回复，不把敏感凭据复制到公开渠道。

## 审核后

审核完成后撤销该账号的全部设备会话，轮换口令和短信审核流程；下一次提交前重新验证。若账号进入删除冷静期，按产品定义保留审计并等待执行或通过强验证取消，不能直接改数据库伪造状态。
