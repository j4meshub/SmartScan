## 使用方式

本文件是后续开发的工作包清单，不替代产品方案、架构文档或当前代码。状态只允许使用：`未开始`、`进行中`、`阻塞`、`等待人工验收`、`完成`、`放弃`。

每次续接先读取 `AGENTS.md`、本文件、`docs/CODEX_PROGRESS.md` 和 Git 状态，从第一个依赖满足且未完成的工作包开始。每个工作包使用独立 `codex/*` 分支和 PR，完成定义以 `AGENTS.md` 为准。

外部能力采用混合闸门：本地 Mock 和契约测试可以让代码继续推进，但真实企微、短信、真机、签名、目标服务器和应用商店验证必须单独记录，不能由模拟结果替代。

## 当前已具备的基线

- 统一仓库结构、FastAPI、CPU Worker、H5、管理后台及 Android/iOS 界面骨架。
- 本地注册登录、Argon2id、手机号 HMAC、会话撤销、RBAC 和基础审计。
- 项目、页面、用户隔离文件、任务租约和基础 CPU 增强。
- 分片上传、断点续传、哈希与图片签名检查、幂等完成。
- OpenCV 文档边缘检测、透视校正和失败时保守回退。
- GitHub/GitLab CI 与单机 Compose 基线。

以上是代码现状，不代表生产、真机、负载或商店验收已经完成。

## 接口、数据和兼容性决策

- 保留 `/v1/uploads/{id}/chunks/{index}` 为正式分片路径，并增加取消上传接口。
- 后续补充验证码申请、刷新令牌、账号删除、企业微信回调、项目删除、缺页分析、导出下载和完整后台接口。
- 作业状态只描述处理生命周期；页面使用独立复核状态。现有 `needs_review` 将通过迁移变为“基础结果可用且页面需要复核”。
- 数据库采用 expand/migrate/contract，生产启动不得继续依赖 `create_all` 代替迁移。
- `/v1` 优先只做兼容性增加；破坏性变更先让所有客户端兼容新旧字段，再删除旧字段。
- 无权访问和不存在的对象统一返回 `404`；跨用户操作全部写入审计。

## 全局验收规则

- Python：Ruff、单元测试、迁移测试、API 集成与权限测试。
- Web：JavaScript 检查、浏览器 E2E、双语、弱网和无障碍。

- 发布前必须验证外部 AI 全关闭的完整流程，以及当前和上一稳定客户端兼容性。
