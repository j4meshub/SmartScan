# 统一身份模型说明

`ACC-001` 将“用户主体”“登录身份”和“已验证手机号”拆成独立职责，同时保持现有 `/v1` 接口、用户 ID、角色、项目归属和会话兼容。本工作包只完成结构拆分与无损迁移；手机号密文、短信供应商、企业微信 OAuth、账号合并和删除流程由后续工作包实现。

## 数据职责

| 结构 | 职责 | 当前约束 |
|---|---|---|
| `users` | 稳定用户主体、角色、状态、语言和生命周期 | 主键继续作为项目、页面、任务、会话和审计的所有者 ID |
| `user_identities` | 登录来源及该来源内的唯一主体 | `(provider, provider_subject)` 全局唯一；同一用户每个 Provider 最多一个身份 |
| `verified_phones` | 已验证手机号的匹配信息、掩码、验证来源和验证时间 | 每个用户当前最多一个已验证手机号；`phone_hmac` 唯一 |

本地登录身份使用 Provider `local`，`provider_subject` 保存用户名，`credential_hash` 保存 Argon2id 密码哈希。其他 Provider 可以不保存 `credential_hash`。超级管理员没有经过手机号验证，因此不会创建 `verified_phones` 记录；旧字段中的 `not-bound` 仅在兼容期保留。

## 迁移策略

迁移 `20261020_0003` 使用 expand/migrate/contract 的前两步：

1. 创建 `verified_phones`，并为 `user_identities` 增加凭据和创建时间。
2. 从旧 `users` 字段回填本地身份及手机号验证事实。
3. 验证同一用户/Provider 不重复、本地身份用户名不冲突，再建立唯一约束。
4. 保留 `users.username`、`users.password_hash`、`users.phone_hmac` 和 `users.phone_masked`，新写入继续双写，供上一版本代码和降级路径使用。

旧库接管使用首个迁移版本的固定列快照，不会随当前 ORM 模型变化。发现身份重复、用户名不一致、唯一手机号冲突或残缺基线时，迁移停止并要求人工处理，不猜测账号归属。

## 运行时兼容

- 注册的用户名冲突从 `user_identities` 判断，手机号冲突从 `verified_phones` 判断。
- 登录和密码校验以本地身份的 `credential_hash` 为准。
- `/v1/me` 和后台用户列表优先从新结构生成原有 `UserView`，响应字段不变。
- 修改密码写入新身份，同时双写旧密码列；注册同时双写旧用户列、新身份和已验证手机号。
- 已有会话、角色、状态、项目所有权和审计关系仍引用原用户 ID，不需要重建。

## 安全与后续边界

本工作包仍只保存手机号 HMAC 与掩码，不保存可恢复手机号，因此不能替代 `ACC-002` 的认证加密、密钥轮换和 HMAC 版本治理。`development_sms` 只表示开发验证码来源，不能视为真实短信验收。企业微信身份绑定、冲突合并、设备会话和账号删除也不得由本次迁移自动推断。

## 回滚

迁移可以降级到 `20261020_0002`：删除新手机号表、身份凭据列和新唯一约束。由于兼容期始终双写旧账号列，降级后本地登录数据仍可使用。正式环境执行降级前仍须在隔离 staging 用备份副本演练；一旦未来 contract 删除旧列，就不能沿用本回滚假设。
