# 文档透视真实样本评估

本文说明 `POC-003` 的固定数据集契约、指标口径、运行方法和人工验收边界。评估框架用于判断现有 CPU 文档边缘检测与透视校正是否达到 v1.4 的可用率目标，不改变生产处理流程，也不把合成测试当作真实业务结论。

## 风险门禁

只有同时满足以下条件，文档透视风险门禁才可判定为通过：

- 数据集经过授权并完成脱敏，且授权范围、审批引用和评估用途均可追溯。
- 固定数据集至少包含 `100` 个有文档正样本，并覆盖实际拍摄条件。
- 正样本透视可用率达到 `95%` 或更高。
- 评估报告、失败样本复核和运行环境已经由人工确认。

合成样本只验证评估器、报告格式和门禁逻辑。即使合成样本达到 `100%`，也不能解除真实样本门禁。当前仓库不包含真实图片，因此 `POC-003` 在框架完成后仍保持“等待人工验收”。

## 样本与授权

清单格式由 `packages/contracts/perspective-evaluation-manifest.schema.json` 定义，示例和本地准备规则位于 `datasets/perspective/`。图片本体放入已被 Git 忽略的 `datasets/perspective/images/`，不得提交到仓库。

每个数据集必须声明：

- `approved=true`：已经获得约定用途的使用批准。
- `deidentified=true`：已经去除手机号、证件号、姓名和其他不必要的个人信息。
- `license`：许可证或内部授权范围。
- `consent_reference`：不含个人信息的审批或同意记录编号。
- `purpose`：本次评估用途。

每个样本必须记录稳定 ID、相对路径、SHA-256、场景分类和人工期望。正样本四角按照左上、右上、右下、左下排列，坐标除以原图宽高后归一化至 `0–1`。负样本只标记不存在文档，不提供四角。

建议真实数据集至少覆盖：浅色与深色桌面、低对比度纸张、明显阴影、轻度遮挡、旋转、梯形畸变、远近距离、不同分辨率、印刷件与手写件，以及无文档背景负样本。数据集版本冻结后，图片和标注变更必须同步更新 SHA-256 与数据集 ID。

## 指标定义

对每个正样本，只有同时满足以下条件才计为“可用”：

1. 算法检测到文档四边形。
2. 预测四角与人工标注四角的均方根像素距离，除以原图对角线后不超过 `0.03`。
3. 透视输出宽和高均不少于 `64` 像素。

报告同时提供：

- 检测召回率：检测到四边形的正样本数除以正样本总数。
- 透视可用率：满足完整可用条件的正样本数除以正样本总数。
- 负样本误检率：被错误检测为文档的负样本数除以负样本总数。
- 单样本处理耗时的 P50、P95 和最大值。
- 评估进程采样得到的峰值 RSS。

负样本误检率和资源指标用于发现回归，但当前 v1.4 开闸条件仍以最少正样本数与透视可用率为准。任何低置信或检测失败结果都保留完整画面并进入复核，不能通过激进裁切提高表面指标。

## 运行方法

准备授权数据集后执行：

```bash
python tools/evaluate_perspective.py datasets/perspective/manifest.json \
  --output reports/perspective \
  --minimum-usable-rate 0.95 \
  --minimum-positive-samples 100 \
  --corner-error-threshold 0.03 \
  --save-previews \
  --fail-below-target
```

命令输出 JSON 和中文 Markdown 报告。报告不写入原始文件路径或个人数据；可选预览位于被 Git 忽略的 `reports/perspective/previews/`，只供授权人员本地复核。`--fail-below-target` 在样本数不足或可用率未达标时返回非零退出码，便于在受控评估环境中作为门禁使用。

## 人工验收清单

- 确认数据来源、授权范围、脱敏过程和审批引用有效。
- 确认至少 `100` 个正样本，并检查场景分布不存在明显偏置。
- 对失败样本和随机通过样本复核四角、裁切内容及文字完整性。
- 记录代码提交、数据集 ID、操作系统、CPU、内存和命令参数。
- 保存报告摘要和审批结论；图片、预览及个人数据不得进入 Git、PR 或公开 CI 附件。
- 可用率未达到 `95%` 时保持门禁关闭，先调整算法、数据分层或产品范围，再重新评估。
