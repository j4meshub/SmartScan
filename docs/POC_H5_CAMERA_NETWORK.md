# H5 相机与弱网续传 POC

## 目标与边界

`POC-002` 验证 H5 可以优先使用浏览器实时后置相机，在能力缺失、授权失败或拍摄失败时始终保留系统相机/文件选择兜底；同时以确定性自动测试证明网络中断后可从服务端已确认分片继续，不重复传输已确认内容。

本工作包不宣称已经通过 Android 企业微信真机、真实 4G/5G、跨地区链路或后台关闭页面恢复验收。这些项目需要真实设备和网络条件，继续保留人工门禁。

## 相机策略

```text
用户打开实时相机
  -> getUserMedia，优先 environment 后置摄像头
  -> ImageCapture 可用：takePhoto
  -> ImageCapture 不可用：从 video 帧绘制 JPEG
  -> 任一步失败：保留 capture=environment 文件输入
```

- 实时相机必须由用户点击触发，不自动申请权限或自动快门。
- 视频元素使用 `playsinline`，避免移动浏览器强制全屏播放。
- 关闭对话框、主动关闭相机或拍摄完成后停止全部媒体轨道。
- 系统相机/文件输入始终存在，不以实时相机能力检测结果隐藏。
- `getUserMedia` 在生产需要 HTTPS 安全上下文；本地 `localhost` 可用于开发。

## 续传策略

- 首次选择文件时创建项目，并把项目 ID 与幂等键写入 `localStorage`。
- 每次重新提交都用同一幂等键查询/创建上传会话，以服务端 `received_chunks` 为确认事实来源。
- 客户端只发送未确认分片；每片和整文件继续使用 SHA-256。
- 网络异常时保留本地断点；完整提交成功后才删除。
- 上传会话过期时只更换幂等键，继续使用原项目，避免产生重复项目。
- 异常或损坏的本地断点 JSON 会被清理，不作为可信服务端状态。

## 自动化场景

`apps/h5/tests/camera.test.js` 覆盖：

- 能力检测始终返回系统拍照文件兜底。
- 后置相机约束、视频绑定、内联播放和媒体轨道释放。
- 不支持实时相机、权限失败时返回稳定错误供界面降级。
- `ImageCapture` 拍摄和 video/canvas JPEG 回退。

`apps/h5/tests/resumable-upload.test.js` 覆盖：

- 三分片文件在第 2 片发送时断网。
- 重新提交沿用原项目与幂等键。
- 服务端返回第 1 片已确认后，客户端不再发送该分片。
- 剩余分片完成后清除本地断点。
- 会话过期更换幂等键但不重复创建项目。
- 浏览器缺少可靠 MIME 时按受支持扩展名回退。

GitHub Actions 和 GitLab CI 使用 Node.js 22 执行上述测试，不需要真实相机硬件或外部网络。

## 人工验收门禁

以下项目仍需真实设备和网络，不得用 Node.js 模拟结果替代：

1. 至少 3 款 Android 手机、2 个企业微信版本测试后置摄像头选择、权限拒绝、重新授权和系统相机兜底。
2. 记录照片分辨率、EXIF 方向、焦点、曝光、反光和遮挡表现。
3. 在 Wi-Fi、4G、5G 及网络切换中中断上传，记录成功率、重试字节、恢复时间，并确认已确认分片不重传。
4. 关闭并重新进入 H5 后，使用同一文件恢复未完成任务。
5. 验证企业微信内置浏览器、系统浏览器和桌面浏览器的中文、英文及无障碍提示。

上述证据完成前，真实弱网与企业微信相机门禁保持“等待人工验收”。
