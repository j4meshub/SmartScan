# Android 身份、Keystore 与用户分区缓存

## 范围

`AND-002` 在 `AND-001` 分层基础上接入本地账号注册、登录、会话恢复、一次性刷新令牌轮换、注销、Android Keystore 和 Room 项目缓存。企业微信 Android 原生授权、账号合并和账号删除入口不属于本工作包；真实短信仍是人工验收门禁。

## 身份流程

Android 实际消费以下 `/v1` 操作，并已登记到兼容矩阵：

- 申请注册验证码；
- 使用手机号、验证码挑战、用户名和密码注册；
- 用户名与密码登录；
- 使用一次性刷新令牌轮换完整设备会话；
- 获取当前用户；
- 注销当前设备会话。

注册或登录返回令牌后，客户端先原子写入加密会话，再调用 `/v1/me` 确认用户主体。当前用户确认失败时立即删除刚写入的会话，不进入已登录界面。应用启动时先尝试恢复当前用户；访问令牌被拒绝时只使用持久化的当前刷新令牌轮换一次，再重新读取当前用户。

刷新响应必须同时提供新访问令牌、新刷新令牌、两类有效期、会话 ID 和设备 ID。缺少任一安全字段都会作为无效响应拒绝，不复用旧刷新令牌。仓储使用互斥锁串行化刷新写入，避免同一进程并发修改加密状态。

## Keystore 边界

会话使用 Android Keystore 中的 AES-256/GCM 密钥加密后写入应用私有 `SharedPreferences`：

- 每次写入使用随机 96 位 IV 和 128 位认证标签；
- 密钥不可导出，明文令牌不写入 Room、文件名、URL 或日志；
- 内存只保留当前会话对象，供请求拦截器读取访问令牌；
- 密文损坏、格式未知或认证失败时删除持久化值并回到未登录状态；
- 注销删除密文和 Keystore 条目。

宿主 JVM 测试通过可替换加密值存储验证令牌轮换、损坏密文回退和清理语义；真实 Android Keystore 仍需模拟器与真机门禁。

## Room 用户隔离

本地项目缓存使用 `(owner_user_id, id)` 复合主键。所有读取、替换和删除方法都必须显式提供非空 `userId`，禁止依赖全局“当前用户”过滤数据库查询。

远端项目读取成功后只替换当前用户分区；网络失败时只查询同一用户分区，绝不回退到其他账号的数据。退出登录无论服务端请求是否成功，都会尝试删除会话与当前用户缓存；一项本地清理失败不会跳过另一项清理，并向界面返回本地存储失败。

当前 Room 数据库版本为 1，只保存可重新下载的项目列表元数据，不保存密码、令牌、手机号明文或扫描原图。后续增加页面和上传队列时必须使用版本化 Room Migration，不能采用破坏性重建处理用户离线任务。
