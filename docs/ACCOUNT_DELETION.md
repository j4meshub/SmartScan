# 账号删除、冷静期与手机号复用隔离

## 流程边界

账号删除采用“申请—冷静期—到期清理”三段流程，不把停用等同于删除：

1. 已登录用户先申请 `purpose=account_deletion` 的短信挑战，再调用 `POST /v1/me/account-deletion`。
2. 服务端核对短信验证号码确属当前用户，拒绝超级管理员，将账号置为 `deleting` 并立即撤销全部访问令牌和刷新令牌。
3. 冷静期固定为 7 天。期间账号不能登录、刷新令牌或访问用户数据。
4. 用户可申请 `purpose=account_deletion_cancel` 的短信挑战，并调用 `POST /v1/auth/account-deletion/cancel` 撤销申请；旧会话不会恢复，需要重新登录。
5. 冷静期届满后，Worker 领取请求，清理登录身份、会话、扫描项目、页面、上传、处理任务和用户文件，最后把请求标记为 `completed`。

接口只返回删除请求 ID、状态和时间点，不返回内部清理路径、手机号摘要或资源明细。取消接口在查找账号前先消费短信挑战，未证明控制该手机号的请求不能据此枚举账号。

## 到期任务与可重入清理

两个 CPU Worker 都会每 30 秒尝试领取一个到期删除请求。也可以执行一次性命令：

```bash
python -m services.api.app.account_deletion --limit 100
```

清理使用以下补偿协议：

- 用户目录先在同一存储卷内原子移动到 `.account-deletion/<request-id>` 隔离目录。
- 仍有 `running` 图像任务时不移动目录也不删数据库，等待任务完成、失败或由租约恢复后再重试。
- 数据库事务按依赖顺序删除分片、任务、上传、页面、项目、刷新令牌、会话、登录身份和已验证手机号。
- `users` 仅保留不可登录的最小墓碑，用随机无关摘要替换兼容手机号字段；历史追加式审计不改写。
- 数据库提交失败时，把本次移动的目录恢复到原位置。
- 数据库提交成功但物理擦除失败时，请求保持 `cleanup_pending`，只保存稳定错误码，后续 Worker 可安全重试。
- 并发 Worker 依靠请求行锁和幂等状态收敛；已经 `completed` 或 `canceled` 的请求不会重复清理。

公开 AI URL、导出等尚未建立的数据类型必须在对应工作包接入同一清理服务后，才能宣称完整生产删除通过。

## 手机号复用隔离

最终清理会把已验证手机号的 HMAC 和密钥版本写入 `phone_reuse_quarantines`，不保留可逆手机号密文。隔离从实际清理时间起计算 30 天；期间本地注册和企业微信新账号创建均拒绝复用。隔离到期后可以注册为全新账号，旧数据不会恢复。

手机号 HMAC Pepper 轮换时，旧 Pepper 至少保留到所有引用该版本的隔离记录过期，并覆盖备份与回滚窗口；提前移除旧 Pepper 会使新注册无法计算旧摘要，从而削弱复用隔离。

## 迁移与回滚

`20261020_0010` 新增删除请求表和手机号复用隔离表，不修改既有用户与资源表。升级后旧客户端仍可使用原有接口；账号删除入口由后续 H5、Android 和 iOS 工作包接入。

降级到 `20261020_0009` 会丢失待处理请求和手机号隔离证据，因此生产降级前必须停止 Worker、导出未完成请求并确认不会放行应被隔离的手机号。已经完成的数据与文件删除不可通过数据库降级恢复，只能依赖合规备份和人工审批。
