# Android 离线队列与分片续传

## 范围

`AND-004` 将 CameraX 保存的应用私有原图接入用户分区 Room 队列，并通过 WorkManager 在网络恢复后创建项目、建立上传会话、补传服务端未确认的分片并完成页面创建。正式分片路径保持 `/v1/uploads/{id}/chunks/{index}`。

本工作包不实现页面编辑、导出或分享；这些能力属于 `AND-005`。真机网络切换、进程强杀和大文件压力仍是人工门禁。

## 持久化模型

Room 数据库从 v1 升级到 v2，新增：

- `local_upload_projects`：以 `(owner_user_id, local_project_id)` 为主键，保存本地项目标题、模式和服务端项目 ID。
- `queued_uploads`：以 `(owner_user_id, id)` 为主键，保存私有原图路径、大小、稳定幂等键、文件哈希、服务端上传 ID、已确认字节数、状态和页面 ID。

v1 到 v2 使用显式 `MIGRATION_1_2`，不使用破坏性重建。所有查询和更新必须同时传入当前用户 ID；注销不会删除未上传原图，用户重新登录后可恢复自己的队列，其他账号不能接管。

队列状态为：

```text
QUEUED
  -> UPLOADING
  -> COMPLETED

UPLOADING -> RETRYING -> UPLOADING
UPLOADING -> WAITING_FOR_LOGIN -> UPLOADING
UPLOADING -> FAILED
```

`FAILED` 只用于本地文件缺失、响应结构冲突等不可安全重试的问题。断网、超时、`408`、`429` 和 `5xx` 保持稳定幂等键并进入指数退避；上传会话过期才生成新幂等键。

## 续传协议

1. 首个待上传页面创建服务端项目并持久化项目 ID。
2. 对原图流式计算 SHA-256，使用稳定幂等键调用 `POST /v1/uploads`。
3. 已有服务端上传 ID 时先调用 `GET /v1/uploads/{id}` 恢复状态。
4. 客户端只跳过服务端 `received_chunks` 明确确认的分片；本地 `uploaded_bytes` 只用于进度展示。
5. 每个分片重新计算 SHA-256，通过 `X-Chunk-Sha256` 发送原始字节，并校验回执的上传 ID、索引、大小和哈希。
6. 全部分片确认后调用 `POST /v1/uploads/{id}/complete`；若完成响应丢失，下一次查询到 `completed + page_id` 后幂等收敛。

分片计划必须满足文件大小、正数分片大小和精确分片总数；服务端返回越界索引或不一致回执时禁止继续。

## WorkManager 与会话

- 每个本地项目使用唯一工作链，`APPEND_OR_REPLACE` 保证同一项目的后续拍摄不会取消正在发送的分片。
- 工作约束要求 `NetworkType.CONNECTED`，瞬时失败使用 WorkManager 指数退避。
- Worker 启动前比较加密会话的 `userId` 与队列所有者；无会话或账号不同会标记等待登录并结束本轮工作。
- API 返回 `401` 时先复用认证仓储的一次性刷新流程。刷新后重试；刷新失败清理会话并保持等待登录。
- 每次登录或启动恢复成功后，重新调度当前用户的未完成项目。

## 文件安全

入队只接受 `files/captures/originals` 规范路径下、大小大于 15 字节的真实文件。路径先解析为 canonical file，再验证位于应用私有根目录，拒绝目录穿越和外部路径。原图上传成功后仍保留，直到后续项目删除流程按持久化清理证据移除。

文件名、幂等键和 WorkManager 数据不包含手机号、用户名或 OCR 文本。令牌仍只由 Keystore 会话提供，并只进入 `Authorization` 请求头。

## 自动化与人工门禁

自动测试覆盖：

- Room 用户隔离、页面顺序、进度、完成状态和 v1→v2 迁移。
- 跳过服务端已确认分片、剩余分片顺序、哈希回执和完成收敛。
- 断网重试保持幂等键、上传过期轮换幂等键、本地文件缺失永久失败。
- Retrofit 分片路径、哈希请求头、二进制请求体和凭据不进入 URL。

以下仍需目标设备和 staging：Wi-Fi/蜂窝切换、飞行模式、进程强杀、系统回收、令牌恰好过期、多个大文件、服务端重启、上传会话过期和磁盘不足。自动测试与 Mock 不能把这些门禁标为通过。

项目创建接口当前没有服务端幂等键。若连接在“服务端已创建、客户端未收到响应”的窗口中断，重试可能产生空项目；在 staging 压力验收前需要决定是否为项目创建增加客户端幂等键。分片与页面完成本身已经具备幂等收敛证据。
