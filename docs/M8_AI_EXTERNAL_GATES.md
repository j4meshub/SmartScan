# M8 视觉 AI 外部门禁与续接清单

## 当前断点

截至主线提交 `a15b78e`，`AI-006～AI-009`、`H5-AI-001`、`DEVX-002`、`AND-AI-001` 和 `IOS-AI-001` 已完成。H5、Android 与 iOS 已使用同一公共 API 实现项目授权、任务创建、候选展示、接受/放弃和版本规则；Provider 关闭或失败时，基础扫描、编辑、预览和导出保持可用。

M8 仍是“进行中”，不是“完成”。剩余 `AI-010`、`AI-011` 和 `AI-012` 都依赖尚未取得的授权固定数据、真实 Provider 或目标设备证据。缺少这些输入时不得用 Mock、合成样本或静态测试替代，也不得提前把专项 AI 接入确定性净化或扫书管线。

## 阻塞矩阵

| 门禁 | 需要提供或确认的外部输入 | 仓库内已有能力 | 通过证据 | 解锁工作 |
|---|---|---|---|---|

| 三端与导出闭环 | 可用的 Android/iOS 真机、测试账号、隔离项目和可导出样本 | 三端统一项目授权、候选决定、基础版本回看与导出 | 至少一条“项目授权→页面任务→候选版本→用户接受→导出”真实 Provider 证据；三端对同一状态解释一致 | 允许 `AI-012` 进入最终验收 |

固定数据原图、手机号、Provider Key、签名材料和内部地址不得提交到仓库。仓库只保存授权/脱敏清单摘要、不可逆数据集指纹、指标报告和不含用户内容的审计证据。真实 Secret 继续通过被 Git 忽略的本机文件或部署 Secret 注入。

## 恢复顺序

1. 准备固定数据集并完成授权、脱敏、来源分组和哈希清单；先运行 POC、EXAM/BOOK 基础指标与 `AI-005`，失败时调整算法路线或产品范围。
2. 试卷基础指标通过后，按 `EXAM-002 → EXAM-003 → AI-010` 顺序实现。`review_cleanup_mask` 只提供区域分类，最终擦除、修补和回退必须由确定性管线执行。
3. 扫书真实固定集与真机指标通过后实现 `AI-011`。`review_book_split` 只复核困难书脊、左右页和页码，最终裁切与去弯曲仍由确定性管线执行。
4. 在隔离环境配置真实 Provider，验证签名 HTTPS 媒体可达、SSRF 边界、费用限制和失败降级；不得把内部网关暴露给客户端或公网入口。
5. 执行 `AI-012`：七类任务固定评估、真实业务闭环、三端一致性、费用/延迟和隐私政策验收。所有证据通过后才能把 M8 标记为“完成”。

## 继续开发时的检查点

收到“继续开发”后，先检查本清单对应输入是否已经提供，并核对 `docs/CODEX_EXECUTION_PLAN.md` 与 `docs/CODEX_PROGRESS.md`：

- 只解锁依赖已经满足的第一个工作包；不要同时把 `AI-010/011/012` 全部改为进行中。
- 真实数据或 Provider 仍缺失时保持“阻塞”，可以补充清单和工具，但不能生成虚假的通过报告。
- 每个专项工作包继续使用独立分支、中文提交和中文 PR；自动检查、真实数据指标和人工真机结论分别记录。
- Provider 关闭、故障或费用超限的完整核心流程必须始终通过，任何专项 AI 失败都不得影响基础预览与导出。
