# iOS 本地队列、后台恢复与分片续传

## 范围

`IOS-004` 把相机保存的不可变原图接入用户分区本地队列，并在前台或系统授予的 `BGProcessingTask` 时间内完成项目创建、上传会话恢复、缺失分片补传和幂等完成。正式分片路径保持 `/v1/uploads/{id}/chunks/{index}`。

页面编辑、PDFKit、系统分享和账号删除属于 `IOS-005`。iOS 后台调度由系统决定，本实现不承诺固定开始时间、持续时长或一定在应用退出后立即完成。

## 本地模型与隔离

队列保存在：

```text
Application Support/SmartScan/upload-queue/<用户 ID SHA-256>/queue.json
```

队列信封固定版本 `1`，包含本地项目、服务端项目 ID、原图/证据 URL、稳定幂等键、整图哈希、服务端上传 ID、进度、状态和页面 ID。写入使用原子替换及首次解锁后的完整文件保护。

入队必须同时满足：原图和证据位于当前用户的 `captures/<用户摘要>/` 目录、两者存在、原图大于 15 字节。路径会标准化并解析符号链接后再验证父目录，拒绝跨用户、目录穿越和外部文件。重复捕获 ID 不会创建第二条队列记录。

状态如下：

```text
queued -> uploading -> completed
          |-> retrying -> uploading
          |-> waiting_for_login -> uploading
          \-> failed
```

## 服务端确认续传

1. 为本地项目创建服务端项目并立即保存 ID。
2. 以流式方式计算原图 SHA-256，使用稳定幂等键创建上传会话。
3. 已有服务端上传 ID 时先查询其状态。
4. 只跳过服务端 `received_chunks` 返回的索引；本地 `uploadedBytes` 不决定跳传。
5. 每个待传分片重新计算 SHA-256，通过 `X-Chunk-Sha256` 发送二进制，并验证回执的上传 ID、索引、字节数和哈希。
6. 完成调用返回丢失时，下次查询到 `completed` 与 `page_id` 后直接收敛为完成，不重复生成页面。

服务端返回的分片大小、总数和已确认索引必须与本地文件严格一致。`401` 仅执行一次刷新令牌轮换后重试；断网、`408`、`429` 和 `5xx` 保持原幂等键。`410` 或明确 `expired` 才清除服务端上传 ID并生成新幂等键。

## BackgroundTasks 边界

应用在启动期注册 `com.j4meshub.smartscan.upload`，Info.plist 将其列入 `BGTaskSchedulerPermittedIdentifiers` 并声明 `processing` 后台模式。任务要求网络连接、不强制外接电源，最早请求时间为 15 分钟后；实际调度完全由 iOS 决定。

任务过期时取消当前 Swift `Task`。上传处理器在每个分片前检查取消，标记为可重试并保留服务端上传 ID、哈希和服务端确认依据。再次登录或应用回到前台会主动恢复当前用户队列。

## 自动化与人工门禁

Simulator 自动测试覆盖用户隔离、重复入队、持久恢复、过期会话轮换、服务端确认分片、回执校验、完成响应收敛、`401` 单次刷新和跨账号暂停。macOS CI 负责 Info.plist、工程生成、Swift 编译和测试。

以下仍需目标 iPhone 与 staging：Wi-Fi/蜂窝切换、飞行模式、进程强杀、锁屏、系统实际调度、任务过期、大文件、磁盘不足、服务端重启、刷新令牌恰好过期和多个项目并发。模拟器与 Mock 不能把这些门禁标为通过。
